Terminal-native coding agent

Loom is a coding agent for your terminal. Point it at any OpenAI-compatible endpoint, hand it a goal, and it reads, edits, runs and verifies — writing every state change to an append-only journal you can replay, rewind and audit.

Built on the opposite of a black box

Most agents ask you to trust a spinner. Loom records what happened: every message, tool call, file hash and verification result lands in a journal that the transcript is merely a projection of.

↺

Replayable by construction

The journal is authoritative. Sessions resume to the exact context they held, and a rewrite of history is visible rather than silent.

◈

Your endpoint, not a vendor list

Chat Completions and Responses protocols are both first-class. Any base URL works, including local models and gateways that support neither discovery nor tool calling.

⌘

Supervision that can say no

An independent reviewer reads the goal, the plan and the evidence. It cannot accept completion while plan items are open or verification fails.

✎

Edits with a paper trail

Hash-protected writes reject stale edits, patches are atomic, and every mutation keeps undo metadata. Conflicts are reported, never clobbered.

⧉

Persistent processes

A named shell keeps its working directory and exports. Monitors stream a long-running build. SSH connections multiplex one authenticated session.

⇄

Honest numbers

Token counts are labelled estimates until the provider reports real usage. No invented progress percentages, no fabricated speed.

Why "Loom"? A loom holds threads under tension and draws one weft through them to make cloth. The agent holds your repository's threads — files, tests, processes — and draws a change through them. The opening banner in the terminal is a frame with warp threads and leaves falling through it.

Running in about a minute

No credentials are needed to see it work; the bundled mock provider is deterministic.

1

Build

Rust 1.75 or newer.

cargo build --release
./target/release/loom
2

Smoke test

Runs offline against the mock provider.

loom run "Say hello" \
  --output text
3

Connect a model

Inside the TUI, add any compatible endpoint.

/providers add local \
  http://127.0.0.1:11434/v1
/model local/my-model
Headless too. The same harness runs in CI: loom run "fix the parser" --effort high --output jsonl. Exit codes are a documented contract — 0 completed, 1 failed, 2 cancelled, 64 usage or config error.
